# فاز ۰۹ — از فایل محلی تا دستهٔ آموزش علّی

این فاز فایل‌های UTF-8 را فقط از فهرست صریح کاربر می‌خواند. هیچ دانلود، جست‌وجوی خودکار پوشه یا مجموعه‌دادهٔ بیرونی وجود ندارد. فایل فارسی، انگلیسی، متن ترکیبی و کد پایتون همگی با `ByteTokenizer` قبلی کد می‌شوند. فایل کد فقط به‌عنوان متن خوانده می‌شود و اجرا نمی‌شود.

## فایل، سند و توکن

هر فایل یک سند مستقل است. `TextDataset` متن اصلی، مسیر، شناسه‌های توکن و SHA-256 محتوا را نگه می‌دارد. فاصله، تورفتگی، بزرگی حروف و حتی تفاوت `\r\n` و `\n` حفظ می‌شود؛ خواندن باینری و سپس UTF-8 مانع تغییر خط جدید می‌شود. فایل خالی و UTF-8 نامعتبر خطا می‌دهند. رشتهٔ شامل فقط فاصله خالی محسوب نمی‌شود، چون فاصله در زبان و کد معنی دارد.

```python
from minicoder.data import TextDataset

documents = TextDataset([
    "examples/synthetic/persian.txt",
    "examples/synthetic/english.txt",
    "examples/synthetic/python_example.py",
    "examples/synthetic/mixed.txt",
], add_bos=True, add_eos=True)
```

افزودن BOS و EOS در `TextDataset` اختیاری و پیش‌فرض آن خاموش است. فرمان آموزش این دو گزینه را روشن می‌کند تا آغاز و پایان هر سند مشخص باشد. مسیر پوشه جایگزین فهرست فایل‌ها نیست و فایل تکراری در همان فهرست رد می‌شود.

## چرا ۱۲۹ توکن برای ۱۲۸ ورودی لازم است؟

اگر طول زمینه `T=128` باشد، یک مثال کامل به ۱۲۹ توکن پیاپی از همان سند نیاز دارد:

`input_ids = tokens[start : start+128]`

`target_ids = tokens[start+1 : start+129]`

مثال کوچک‌تر با `T=3`:

```text
پنجره: [A,B,C,D]
ورودی: [A,B,C]
هدف:   [B,C,D]
```

هر خروجی باید توکن بعدی را پیش‌بینی کند. برابر گرفتن ورودی و هدف اشتباه است. هدف‌ها در dataset یک بار جابه‌جا شده‌اند و Trainer یا GPT نباید دوباره آن‌ها را شیفت بدهد. GPT قبلی دقیقاً همین قرارداد را دارد.

## فاصلهٔ پنجره‌ها و سند کوتاه

`CausalLanguageModelDataset` روی خودِ متن سندها پنجره می‌سازد و هیچ پنجره‌ای از مرز دو سند رد نمی‌شود. شروع‌ها با `stride` مشخص می‌شوند:

| مقدار stride | رفتار |
| --- | --- |
| `1` | پنجرهٔ لغزان با هم‌پوشانی زیاد |
| `T`، پیش‌فرض | قطعه‌های ورودی بدون هم‌پوشانی؛ یک توکن مرزی برای اتصال هدف‌ها مشترک است |
| `T+1` | پنجره‌های کاملِ بدون توکن مشترک؛ جفتِ مرزی بین قطعه‌ها آموزش داده نمی‌شود |

با `stride=T`، آخرین هدف پنجرهٔ اول همان اولین ورودی پنجرهٔ بعدی است. این هم‌پوشانی داخل یک بخش داده طبیعی است؛ هدف‌های واقعی پشت سر هم پوشش داده می‌شوند. ایجاد پنجره‌ها پیش از تفکیک و پخش تصادفی آن‌ها بین آموزش و اعتبارسنجی باعث نشت می‌شود و انجام نمی‌شود.

سیاست `short_document_policy="pad"` انتهای کوتاه را از سمت راست پر می‌کند. برای متن `ABC` و `T=5`:

```text
ورودی: [A, B, PAD, PAD, PAD]
هدف:   [B, C, PAD, PAD, PAD]
```

در این مثال فقط دو هدف معتبر داریم. می‌توان مقدار هدف‌های حذف‌شده را با `ignore_index=-100` عوض کرد؛ ورودی‌های پرکننده همچنان PAD معتبرند. سیاست `drop` هر پنجرهٔ کوتاه را حذف می‌کند. سندی با کمتر از دو توکن هیچ جفت ورودی و هدف ندارد؛ اگر پس از اعمال سیاست هیچ مثالی نماند، خطای روشن ایجاد می‌شود.

## جداسازی پیش از پنجره‌سازی

```python
from minicoder.data import CausalLanguageModelDataset, split_documents

train_docs, validation_docs = split_documents(documents, validation_fraction=0.25, seed=42)
train_data = CausalLanguageModelDataset(train_docs, sequence_length=128)
validation_data = CausalLanguageModelDataset(validation_docs, sequence_length=128)
```

تفکیک روی گروه‌های سند انجام می‌شود. نسخه‌های دقیقاً یکسان از یک متن با استفاده از هش در یک گروه قرار می‌گیرند و به دو سمت تقسیم نمی‌شوند. دست‌کم دو محتوای متفاوت لازم است؛ یک سند به‌طور خودکار به پنجره‌های آموزش و اعتبارسنجیِ هم‌پوشان شکسته نمی‌شود. اگر تنها یک سند دارید، پیش از ورود به pipeline آن را آگاهانه به اسناد مستقل تقسیم کنید.

اشتراک واژگان بین دو بخش نشت محسوب نمی‌شود؛ مسئله، استفادهٔ دوباره از همان نمونه یا موقعیتِ منبع است. تشابه جزئی و نسخه‌های ویرایش‌شدهٔ سندها خودکار تشخیص داده نمی‌شود و برای دادهٔ واقعی به بازبینی و حذف تکرارهای نزدیک نیاز دارید. سهم اعتبارسنجی بر تعداد گروه‌های سند اعمال می‌شود و الزاماً همان سهم توکن‌ها نیست.

## دسته و نمونه‌گیری تکرارپذیر

```python
from minicoder.data import create_dataloader

loader = create_dataloader(train_data, batch_size=2, shuffle=True, seed=42)
input_ids, target_ids = next(iter(loader))
assert input_ids.shape == target_ids.shape == (2, 128)
```

تنسورها `torch.long` و روی CPU هستند. آخرین دسته ممکن است کوچک‌تر باشد. حذف آن با `drop_last=True` اختیاری است و اگر تمام دسته‌ها حذف شوند خطا می‌گیریم.

نمونه‌گیر در هر epoch با بذر `seed+epoch` ترتیب را می‌سازد و مکان دستهٔ بعدی را نگه می‌دارد. دو DataLoader تازه با داده، بذر و تنظیمات یکسان، همان ترتیب را می‌دهند. `num_workers=0` و نبود پیش‌خوانی، ذخیرهٔ مکان دقیق برای resume را ممکن می‌کند. حالت نمونه‌گیر و مولد اختصاصی DataLoader در checkpoint فاز دهم ذخیره می‌شود.

پنجره‌ها تنبل‌اند: همهٔ تنسورهای پنجره‌ها از قبل در حافظه ساخته نمی‌شوند. فقط شمارش تجمعی مثال‌های هر سند و توکن‌های متن نگه داشته می‌شوند. سقف پیش‌فرض هر فایل ۲ MiB و مجموع فایل‌ها ۸ MiB است؛ این سقف‌ها در `TextDataset` قابل تنظیم‌اند. این پیاده‌سازی همچنان درون‌حافظه‌ای است و برای آرشیوهای عظیم طراحی نشده است.

## دادهٔ حساس و مجوز

فقط فایل‌هایی را معرفی کنید که اجازهٔ خواندن و استفادهٔ آموزشی از آن‌ها دارید. گذرواژه، کلید API، کلید خصوصی و سایر اطلاعات محرمانه را پیش از ورود به داده حذف کنید. بررسی مقدماتی الگوهای آشکار مانند تخصیص password، api_key و secret را رد می‌کند و مقدار حساس را چاپ نمی‌کند؛ این بررسی تضمین تشخیص همهٔ رازها نیست و جای بازبینی انسان را نمی‌گیرد.

محلی بودن فایل به‌تنهایی مجوز آموزش ایجاد نمی‌کند. منشأ متن، شرایط مجوز، الزام انتساب و محدودیت‌های استفاده را ثبت و بررسی کنید. دادهٔ خصوصی یا دارای مجوز نامتناسب را وارد پیکره نکنید. هیچ مسیر خصوصی بدون معرفی صریح فایل خوانده نمی‌شود.
