# فاز ۰۸ — نخستین معماری کامل GPT

`MiniCoderGPT` اجزای قبلی را در یک مسیر کامل از شناسهٔ توکن تا امتیاز توکن بعدی قرار می‌دهد. همهٔ وزن‌ها تازه ساخته می‌شوند. داشتن معماری کامل با داشتن مدل آموزش‌دیده متفاوت است: این نسخه هنوز دانشی از زبان یا برنامه‌نویسی یاد نگرفته است.

## معماری و تنظیمات

```text
شناسه‌ها (B,T)
 → جدول توکن + جدول موقعیت (B,T,128)
 → چهار بلوک Pre-LayerNorm (B,T,128)
 → LayerNorm نهایی (B,T,128)
 → سر خطی زبان، دارای بایاس (B,T,260)
```

`ModelConfig` یک قرارداد تغییرناپذیر برای ساخت مدل است. اندازهٔ واژگان پیش‌فرض از توکن‌ساز خوانده می‌شود. تنظیمات پیش‌فرض عبارت‌اند از: ۲۶۰ توکن، بُعد ۱۲۸، چهار سر، چهار بلوک، بُعد میانی ۵۱۲ و سقف ۱۲۸ توکن. اندازه‌ها باید صحیح مثبت باشند و بُعد بردار بر تعداد سرها بخش‌پذیر باشد. `layer_norm_eps` مثبت و متناهی است. معماری کوچک‌تر برای آزمایش نیز قابل ساخت است:

```python
from minicoder.model import MiniCoderGPT, ModelConfig

config = ModelConfig(embedding_dim=32, num_heads=4, num_layers=2,
                     hidden_dim=64, max_context_length=64)
model = MiniCoderGPT(config)
```

مدل از ماژول‌های قبلی استفاده می‌کند؛ همهٔ عملیات روی CPU اجرا می‌شوند. دسته و طول دنباله باید غیرصفر باشند. طول می‌تواند از یک تا سقف زمینه تغییر کند. شناسه‌های ورودی باید از نوع `int32` یا `int64`، دوبعدی و داخل واژگان باشند.

## logits چیست؟

در هر جایگاه، سر خروجی یک امتیاز برای هر شناسهٔ ممکن می‌سازد. این امتیازهای خام logits نام دارند؛ احتمال نیستند و می‌توانند مثبت یا منفی باشند. با softmax روی محور واژگان، جمع احتمال‌ها یک می‌شود. `logits[b,t,k]` امتیاز توکن `k` به‌عنوان توکن بعد از ورودی جایگاه `t` است.

مثلاً برای سه توکن فرضی با logits برابر `[2,1,0]`، احتمال‌ها تقریباً `[0.665,0.245,0.090]` هستند. بیشترین امتیاز لزوماً پیش‌بینی درست نیست، به‌ویژه وقتی وزن‌ها هنوز تصادفی‌اند. در توکن‌سازی بایتی، یک شناسهٔ خروجی نیز لزوماً به‌تنهایی یک نویسهٔ UTF-8 معتبر نمی‌سازد.

رابط خروجی همیشه یک زوج است:

```python
logits, loss = model(input_ids)             # loss برابر None
logits, loss = model(input_ids, target_ids) # loss یک عدد قابل مشتق
```

## قرارداد صریحِ توکن بعدی: شیفت فقط بیرون مدل

برای دنبالهٔ کامل `S`، ورودی `S[:,:-1]` و هدف `S[:,1:]` است. مدل هیچ جابه‌جایی داخلی انجام نمی‌دهد. اگر آماده‌ساز داده هدف را جابه‌جا کرده است، آن را دوباره تغییر ندهید. شکل هدف باید دقیقاً با شکل ورودی برابر باشد. این قرارداد حتی برای یک جایگاه هم معتبر است، زیرا هدفِ آن جایگاه می‌تواند توکن بعدیِ بیرون ورودی باشد.

```text
دنباله:  [BOS, A, B, EOS, PAD]
ورودی:   [BOS, A, B, EOS]
هدف:     [ A,  B, EOS, PAD]
```

در جایگاه اول، مدل با دیدن BOS باید A را پیش‌بینی کند؛ در جایگاه دوم با دیدن BOS و A باید B را پیش‌بینی کند. هدف EOS نیز یک توکن معتبر برای یادگیری پایان است. برابر قرار دادن ورودی و هدف، وظیفهٔ بازسازی توکن فعلی ایجاد می‌کند و قرارداد این پروژه برای توکن بعدی را رعایت نمی‌کند.

```python
import torch
from minicoder.tokenizer import BOS_ID, EOS_ID, PAD_ID

sequence = torch.tensor([[BOS_ID, 65, 66, EOS_ID, PAD_ID]])
input_ids, target_ids = sequence[:, :-1], sequence[:, 1:]
logits, loss = model(input_ids, target_ids)
loss.backward()
```

ماسک علّی ضروری است: اگر جایگاه اول بتواند ورودی جایگاه دوم را ببیند، به پاسخ صحیح هدفش دسترسی مستقیم خواهد داشت. تست‌های GPT تغییر آینده و سازگاری خروجی پیشوند با اجرای جداگانهٔ همان پیشوند را بررسی می‌کنند.

## آنتروپی متقاطع و padding

برای هدف صحیح `y`، خطای یک جایگاه:

`L = -log p(y) = logsumexp(logits) - logits[y]`

کاهش این خطا احتمال توکن هدف را نسبت به گزینه‌های دیگر افزایش می‌دهد. ورودی تابع `cross_entropy` خودِ logits است؛ پیش از آن softmax نمی‌زنیم. میانگین فقط روی هدف‌های معتبر گرفته می‌شود.

`ignore_index` در تنظیمات پیش‌فرض برابر `PAD_ID=256` است. می‌توان مثلاً `-100` را نیز انتخاب کرد؛ این مقدار خارج از واژگان فقط در هدف مجاز است و ورودی embedding نباید آن را داشته باشد. اگر همهٔ هدف‌ها نادیده گرفته شوند، قرارداد مدل خطای صفرِ قابل مشتق است تا میانگینِ مجموعهٔ خالی NaN نسازد.

نادیده گرفتن PAD در خطا با ماسک padding در توجه فرق دارد. در این فاز ماسک توجه فقط علّی است؛ padding را در سمت راست قرار دهید تا وارد گذشتهٔ توکن‌های واقعی نشود. پدگذاری سمت چپ نیازمند تصمیم جداگانه دربارهٔ ماسک و موقعیت‌هاست و توسط این رابط خودکار مدیریت نمی‌شود.

در درس ۲۶ با بذر ثابت ۴۲، خطای نمونهٔ دست‌ساز حدود `6.35511` بود و محاسبهٔ دستی از `log_softmax` همان مقدار را داد. این عدد معیار کیفیت زبانی نیست؛ مثال فقط درستی مسیر محاسبه و گرادیان را نشان می‌دهد و به‌روزرسانی وزن ندارد.

## شمارش پارامترها و اشتراک وزن

| بخش مدل پیش‌فرض | تعداد پارامتر |
| --- | ---: |
| جدول توکن | ۳۳٬۲۸۰ |
| جدول موقعیت | ۱۶٬۳۸۴ |
| چهار بلوک، هر کدام ۱۹۸٬۲۷۲ | ۷۹۳٬۰۸۸ |
| LayerNorm نهایی | ۲۵۶ |
| سر خروجی، وزن و بایاس | ۳۳٬۵۴۰ |
| مجموع | ۸۷۶٬۵۴۸ |

با نمادهای `V,D,C,F,L` برای واژگان، بُعد بردار، سقف زمینه، بُعد میانی و تعداد بلوک‌ها، شمارش بدون اشتراک وزن چنین است:

`VD + CD + L(4D² + 2DF + F + 9D) + 2D + VD + V`

اشتراک وزن به‌طور پیش‌فرض خاموش است. با `ModelConfig(tie_weights=True)`، وزن `nn.Linear` سر خروجی و وزن جدول توکن واقعاً همان `Parameter` می‌شوند؛ فقط یک کپی مساوی نیستند. بایاس سر خروجی مستقل می‌ماند. بنابراین `VD=33,280` پارامتر از شمارش کم می‌شود و مجموع به **۸۴۳٬۲۶۸** می‌رسد. ویژگی `trainable_parameter_count` و پیمایش استاندارد `parameters()` پارامتر مشترک را یک بار می‌شمارند.

## ذخیره و بارگذاری وزن‌های خودمان

معماری هنگام بارگذاری باید یکسان باشد؛ برای همین تنظیمات را همراه `state_dict` نگه دارید:

```python
from dataclasses import asdict
import torch
from minicoder.model import MiniCoderGPT, ModelConfig

torch.save({"config": asdict(model.config), "state_dict": model.state_dict()}, "local_model.pt")
saved = torch.load("local_model.pt", map_location="cpu", weights_only=True)
restored = MiniCoderGPT(ModelConfig(**saved["config"]))
restored.load_state_dict(saved["state_dict"])
```

این فایل فقط وزن‌های همین اجرای محلی را نگه می‌دارد. هیچ وزن ازپیش‌آماده‌ای دریافت نمی‌شود. تست‌ها ذخیره و بارگذاری را هم با اشتراک وزن و هم بدون آن، با برابری دقیق خروجی‌ها بررسی می‌کنند.
