# فاز ۰۷ — بلوک ترنسفورمر با Pre-LayerNorm

بلوک ترنسفورمر دو نوع پردازش را کنار هم می‌گذارد: توجه اطلاعات جایگاه‌های مجاز را ترکیب می‌کند و شبکهٔ پیش‌خور ویژگی‌های هر جایگاه را به‌صورت غیرخطی تغییر می‌دهد. در این پروژه همان `MultiHeadCausalAttention` و `FeedForward` فازهای قبل به کار می‌روند و دوباره پیاده‌سازی نشده‌اند.

## مسیر دقیق بلوک

```text
ورودی X
  ├─────────────────────────────┐
  └→ LayerNorm → توجه چندسر ──── جمع → U
                                    ├─────────────────────────┐
                                    └→ LayerNorm → پیش‌خور ─── جمع → Y
```

روابط دقیق:

`U = X + Attention(LayerNorm₁(X))`

`Y = U + FeedForward(LayerNorm₂(U))`

نام Pre-LayerNorm یعنی نرمال‌سازی پیش از هر شاخه انجام می‌شود. پس از جمع دوم در خود بلوک نرمال‌سازی اضافه‌ای نداریم. شکل در همهٔ مسیرهای اصلی `(B,T,128)` باقی می‌ماند، پس جمع‌ها معتبرند.

## LayerNorm چه چیزی را نرمال می‌کند؟

برای یک بردار توکن `x` با `D` ویژگی:

`μ = Σx[j] / D`

`σ² = Σ(x[j]-μ)² / D`

`LayerNorm(x)[j] = γ[j] × (x[j]-μ) / √(σ²+ε) + β[j]`

در این محاسبه واریانس با مخرج `D` به کار می‌رود. `ε` عدد کوچک مثبت برای جلوگیری از تقسیم بر صفر است. `γ` و `β` دو بردار قابل یادگیری‌اند و در ابتدا به‌ترتیب یک و صفرند. به همین دلیل در شروع، میانگین خروجی تقریباً صفر و واریانس تقریباً یک است؛ پس از یادگیری این دو بردار، الزاماً چنین نخواهد بود.

برای ورودی `(B,T,D)` میانگین و واریانس جداگانه روی محور آخر محاسبه می‌شوند. هیچ آماری از آینده یا نمونه‌های دیگر دسته به جایگاه فعلی نمی‌رسد. مثلاً `[1,2,4,8]` میانگین `3.75` دارد و پس از نرمال‌سازی تقریباً به `[-1.026,-0.653,0.093,1.585]` تبدیل می‌شود.

LayerNorm مقیاس ورودی شاخه‌ها را کنترل می‌کند و می‌تواند آموزش را پایدارتر کند. این کار به‌تنهایی تضمین همگرایی نیست و برخلاف BatchNorm، نیازی به آمار جاریِ کل دسته ندارد.

## چرا اتصال باقیمانده مهم است؟

در `y = x + f(x)`، شاخه فقط تغییر لازم نسبت به ورودی را می‌سازد. اگر `f(x)=0` باشد، ورودی بدون تغییر عبور می‌کند. مشتق نیز مسیر مستقیمی دارد:

`∂y/∂x = I + ∂f/∂x`

برای مثال اگر `f(x)=0.1x²` باشد، مشتق `1+0.2x` است. وجود بخش همانی به عبور گرادیان از شبکه‌های عمیق کمک می‌کند. تستی در پروژه تمام پارامترهای دو شاخه را صفر می‌کند و برابری دقیق خروجی با ورودی و گرادیان همانی را بررسی می‌کند.

## علیت و پشته کردن بلوک‌ها

LayerNorm و FeedForward فقط درون ویژگی‌های هر جایگاه کار می‌کنند. توجه هم آینده را ماسک می‌کند. بنابراین جمع این عملیات و تکرار چند بلوک، دسترسی به آینده ایجاد نمی‌کند. تغییر آینده و گرادیانِ ورودی آینده از خطای گذشته در سطح بلوک تست شده‌اند.

هر بلوک در پشته می‌تواند نمایش ساخته‌شده توسط بلوک قبلی را دوباره ترکیب و تبدیل کند. بلوک‌های مختلف وزن‌های جداگانه دارند؛ درون هر بلوک، وزن‌ها بین جایگاه‌های دنباله مشترک‌اند. تعداد بیشتر بلوک‌ها هزینه و ظرفیت را افزایش می‌دهد، اما وزن‌های تصادفیِ بلوک‌های بیشتر به‌خودی‌خود دانش تولید نمی‌کنند.

## پارامترها و استفاده

| بخش یک بلوک پیش‌فرض | تعداد پارامتر |
| --- | ---: |
| توجه چهارسر | ۶۶٬۰۴۸ |
| شبکهٔ پیش‌خور | ۱۳۱٬۷۱۲ |
| دو LayerNorm، هر کدام `2×128` | ۵۱۲ |
| مجموع | ۱۹۸٬۲۷۲ |

اتصال باقیمانده پارامتر ندارد. با نمادهای `D` برای بُعد بردار و `F` برای بُعد میانی، شمارش بلوک برابر `4D² + 2DF + F + 9D` است.

```python
import torch
from minicoder.model import CombinedEmbedding, TransformerBlock
from minicoder.tokenizer import ByteTokenizer

tokenizer = ByteTokenizer()
ids = torch.tensor([tokenizer.encode("سلام")], dtype=torch.long)
embeddings = CombinedEmbedding()
block = TransformerBlock()
y = block(embeddings(ids))
assert y.shape == (1, 8, 128)
y.square().mean().backward()
```

پس‌انتشار از هر دو شاخه و جمع‌ها عبور می‌کند و به جدول‌های embedding هم می‌رسد. این یک خطای ساختگی برای مشاهدهٔ گرادیان است و آموزش زبان محسوب نمی‌شود.
